What "Redacting" a PDF Actually Means

To redact a document is to remove specific information from it before sharing — a name, an address, an account number, a salary figure. The key word is remove. A proper redaction does not merely cover the text; it destroys it, so that no one can retrieve what was underneath.

This distinction is where almost every redaction failure comes from. There are two ways to "black out" text, and only one of them is real.

The Wrong Way: Why a Black Box Doesn't Work

Open a PDF in a standard editor, draw a black rectangle over a name, save, and it looks redacted. It isn't. That black box is just another object drawn on top of the page. The original text is still in the file, at its original position, in the document's text layer.

Anyone who receives that file can recover the text in seconds — by selecting and copying the area, by running the file through pdftotext, or by opening it in another editor and deleting the box. This is the cause of nearly every famous redaction leak in court filings and government documents. We break down the mechanism in detail in The Black Box Flaw.

The only reliable way to redact a PDF is to flatten the page to an image and burn the redaction into the pixels, so there is no text layer left to recover. That is called rasterization, and it is what separates a real redaction from a cosmetic one.

The rule of thumb: if you can still select or search for the text after redacting, it was never removed. A genuine redaction leaves nothing behind to select.

How to Verify Your Redaction Actually Worked

Never trust a redaction you haven't checked. Two quick tests confirm the text is really gone:

  • Try to select it. Open the finished PDF and drag your cursor across a redacted area, then paste into a text field. If nothing comes out, the text was removed. If the hidden words appear, the redaction failed.
  • Run pdftotext. On any computer with the tool installed, run pdftotext redacted.pdf - and search the output for something you removed. It should not be there.

RedactLocal does this check for you automatically: after export, it re-opens the finished file and reports the number of selectable characters, text operators and embedded fonts it can find. On a correct redaction, those counts are zero.

Don't Forget Metadata and Hidden Layers

Visible text is not the only place information hides in a PDF. Before you share a document, be aware of three less obvious sources:

  • The text layer under scans. A scanned document that has been run through OCR contains a searchable text layer even though it looks like an image. Redact it as carefully as a native PDF.
  • Metadata. Author name, software, and creation timestamps are stored in the file's properties. Rasterizing each page on export, as RedactLocal does, rebuilds the document from images and drops the original page-level text and structure in the process.
  • Earlier revisions. Some PDFs retain previous versions of edited content. A redaction that destroys the current text but leaves an old revision intact has not done its job — another reason a flattened, rebuilt output is safer than an edited original.
